=== CiviEvent Widget Changes ===

= 5.2.2 =
* **Fix:** `upcoming_only="0"` loads the most recent past and nearest future events (split queries + `limit`) instead of the oldest rows in the database. No separate date-window shortcode attributes — control volume with **`limit`** only.
* **Fix:** "Today" uses the WordPress site timezone (`wp_date` / `current_time`).
* Calendar mode with past events still raises the fetch **`limit`** to at least **500** when it would otherwise be lower.

= 5.2.1 =
* **Fix:** `upcoming_only="0"` on sites with many historical events no longer returns only the oldest events (superseded by 5.2.2 limit-based split queries).
* **Fix:** "Today" for the upcoming-only filter uses the WordPress site timezone instead of the PHP default timezone.

= 5.2 =
* **`[civievent_widget]` `limit`:** default is **100** for both list and **`style="calendar-month"`** (previously the list default was 5).
* Shortcode attributes **`default_image`** (single URL) and **`default_images`** (pipe- or newline-separated URLs) supply placeholder images when the event has no Civi image; multi-URL lists are distributed per event via a stable hash. Filter: `cib_civievent_default_image_pool`. Template variable `{$event.image_is_default}`; placeholder images use `<img class="civievent-widget-image-default">`.
* Shortcode attribute **`upcoming_only`** (default **true**): when true, the widget only loads events whose start date is today or later. Set to **`0`**, **`false`**, **`no`**, or **`off`** to include past events. Use that with **`style="calendar-month"`** so the grid can show prior months; list layout defaults stay upcoming-only.
* New shortcode option: `style="calendar-month"` on `[civievent_widget]` renders a month grid with prev/next and month/year controls; click a day to open a dialog with event details (register / more info).
* Refactor: `[civievent_widget]` uses one Smarty render path for both default list and **`style="calendar-month"`**; list layout is `templates/list.html` with `{foreach from=$events}`. The calendar grid script reads **`$payload_json`** (built in PHP alongside the rest of the template context). Month/year bounds are computed in the embedded script from the parsed JSON’s **`events`** array.
* **Breaking if you used a custom inner template on `[civievent_widget]`:** inner content must be a **full** widget template (like the default `templates/list.html`), not a single-card fragment. Loop with `{foreach from=$events item=event}` and use `{$event.*}` inside the loop.

= 5.0 =
* Complete rewrite - no single events, just event list
* Template engine: [civievent_widget]...[/civievent_widget] and [civievent_single_widget]...[/civievent_single_widget] now accept inner HTML templates with {event.*} tokens — no server edits needed to customise the layout
* Bug fix: $return undefined in locationInfo() caused PHP warnings on events with no address
* Bug fix: $okOptions undefined in custom-filter code path made that branch a fatal error
* Bug fix: regFix() was silently discarding the spacer div above the button row (= overwriting $reg instead of appending)
* Bug fix: error_log() spam on every page load from the double-execution workaround in civievent_single_widget_shortcode
* Security: esc_url() on image URLs in both widgets
* Security: esc_attr() on og:image, og:description, and description meta tag values
* Security: esc_js() on event data embedded in social-share onclick handlers
